# 文鳥♬文鳥♬文鳥って嬉しいな♪

**おもちと学ぶ文鳥図鑑**。写真で学ぶ図鑑、文鳥アート工房、状態・関係・記憶から自律して暮らす「おもちの文鳥ぐらし」を一つの静的サイトにまとめています。

- 想定公開URL: https://djnaoyaman.github.io/buncho-ureshi/
- 対象リポジトリ: https://github.com/djnaoyaman/buncho-ureshi
- 公開準備時点の根拠は [検証記録](docs/QA.md)、以後の実行結果は [GitHub Actions](https://github.com/djnaoyaman/buncho-ureshi/actions/workflows/pages.yml) を参照。URLの記載だけで公開済みとはしません。

## ローカルで起動

Node.js 22以上。ランタイム用の外部ライブラリ・サービス・秘密鍵・課金APIは使いません。

```sh
npm ci
npm run check
npm test
npm run build
npm run dev
# http://127.0.0.1:4173/buncho-ureshi/
```

`dist/` が配信用。`scripts/build.mjs` が46個の静的ページ、サイトマップ、404、ページ別メタデータを生成します。記事本文はJavaScriptなしでも読めます。ゲームと工房にはJavaScriptが必要です。開発サーバーも本番と同じ `/buncho-ureshi/` サブパスを使用します。

## 三つの機能

### 文鳥図鑑

37項目、30問（写真問題10問）、重複を除いた実写写真42点。まず見る／基本を知る／もっと調べる、ふりがな、端末音声の読み上げ、専門用語、出典・確認日、検索、分類・お気に入り、関連記事、観察ミッション、体の地図。体の7か所は実写写真の確認済み範囲を拡大し、元写真の位置とクレジットも示します。耳の穴が羽毛に隠れることは、見えているかのように扱いません。サイト内検索は主要9セクションと記事を対象にし、検索URL・履歴・空欄／該当なしの案内に対応します。ライセンス確認済みの約12秒の実音入り文鳥映像があります。合成音を本物の鳥の声として紹介しません。

現実のおもちは、娘さんのペットである**メスの白文鳥**。年齢・誕生日・性格・好物・本人写真・観察日記は未提供です。一般写真をおもち本人として扱わず、架空の実話や娘さんの発言を掲載しません。観察室の案内はオリジナルイラストです。利用者が書く観察ノートはその端末にだけ保存され、投稿されません。

### 文鳥アート工房

現在のOMOCHI TOUCHのソースを読み、写真配置・造形・背景／配色・音楽選択・制作段階の音・操作を戻す・作り直す・保存／共有・タッチ対応という発想を独自の文鳥工房へ引き継ぎました。白いウェスティと白文鳥は別の存在です。旧サイトの素材・音源・プロフィールはコピーしていません。

初期6テンプレート、8背景、8配色、加工・保存に対応する写真26点、オリジナル鳥／植物造形。移動・拡縮・回転・重なり・複製・削除・文字編集・色調整・クリッピング、Undo/Redo、正方形／縦長PNG、必要な写真クレジットを含む画像、対応環境の共有とダウンロード代替。BGM3曲と操作音はオリジナルの合成音で、利用者が再生したときだけ鳴ります。

保存データは既知の項目だけを許可し、読み込み前に64,000 UTF-16コード単位以下に制限します。壊れた保存は確認つきの「作り直す」まで上書きしません。画像の読み込み／デコードに失敗した場合や、クレジット全文が画像に収まらない場合はPNG出力を止め、作者名やURLを黙って削りません。編集中・ドラッグ中の変更で古いPNGを無効にします。

参照元の現行コードには写真の色調整・Redoがないため、これらは**追加機能**です。詳しい継承表、参照コミットのblob、ライセンス制約、実画面検証の状況は [工房仕様](docs/STUDIO.md)。

### おもちの文鳥ぐらし

15実秒＝1ゲーム時間。性格・欲求・気分・相手ごとの親しさ／信頼／相性・最近の記憶・保護された節目から行動と返答を選びます。自由入力は限定的な話題・キーワード判定であり、万能なAIではありません。有料AIやキー入力なしで動きます。

メスのおもちから始まり、外来のオスを迎えて名づけ、自律した交流→つがい→条件つき産卵→孵化→幼鳥→成鳥へ。卵・ひな・幼鳥・成鳥は、それぞれ異なるオリジナルの図形で示します。親子・きょうだい・祖先・いとこなど、既知の共通祖先がある鳥同士は繁殖しません。遺伝のシミュレーションではありません。性格、成長、会話、繁殖、日記は**ゲーム上の創作・簡略化で、現実の飼育手順ではありません**。

- 居住10羽・来訪2羽、保存する全名簿128羽が上限。巣立ち／再訪で庭の人数を調整し、古い鳥の名前・家系は消しません。全名簿上限後は新しい卵・来訪者を増やさず、既存の暮らしを続けます。
- 最近の日記240件、最近の記憶16件＋大切な節目16件／羽。無制限に増やしません。
- 閉じたあとは動作せず、次の起動時に最大576ゲーム時間（実時間2時間24分相当）を順に計算。長い不在は罰にならず、死亡や強い苦痛を描きません。自分で食事・休息します。
- `src/game-store.js` のIndexedDB原子的トランザクション、またはWeb Locks＋localStorageでタブ更新を直列化。既存のlocalStorage保存は、後からIndexedDBが利用可能になっても同じ保存先を維持します。IndexedDBの失敗・破損・更新待ちを、別の保存先や新しい庭へ黙って切り替えません。既存の保存がなく永続保存も使えない場合だけ、非永続の単独タブモードを明示します。
- 世界の版は1。ID、名前、関係、家系、成長、記憶、日記、時刻、設定をJSON保存。読み込みと書き出しは共通の4,000,000 UTF-8バイト上限。壊れた形式・不明な項目や版・循環家系・不正な参照／時刻／カウンターを拒否し、今の世界を壊しません。
- 読み込みファイルの選び直しでは最後の要求だけを反映し、画面を離れた後の遅い読み込みを中止します。別タブが庭そのものを入れ替えた場合は`worldId`を検査し、古い画面の改名などを別の鳥へ適用しません。
- `game/?qa=1` の「保存・設定」の折りたたみ内に検証用1000時間ボタン。通常画面には出ません。

## 内容を追加・変更する

| 対象                   | ファイル／方法                                                                                                                                           |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 記事                   | `src/data/articles.js`。一意のid、category、summary、body、deep、terms、sources、checkedAt、photos、related、missionを追加。rubyは本文に記述             |
| 写真                   | `public/photos/` と `src/data/photos.js`。個別ライセンス、作者、元ページ、同定を確認し、[素材台帳](docs/ASSETS.md)へ記録。自然色の図鑑と加工アートを区別 |
| クイズ                 | `src/data/quizzes.js`。answerは0始まり。解説と関連記事idを必須にし、写真／図の内容と一致させる                                                           |
| おもち本人の写真       | 家族から本人と確認した写真を別IDで追加。撮影者の許可・撮影日・本人確認を台帳に残し、観察室だけに明示して配置。一般写真のラベルを本人に書き換えない       |
| ゲームの条件           | `src/engine.js`。TICK_MS、LIMITS、行動選択、つがい・成長条件を変更後、全単体・ブラウザテストを再実行                                                     |
| 会話・日記             | `src/engine.js`の返答ルールと表示。名前はIDから解決するため改名後も履歴がつながる。自由入力に危険な評価や外部送信を追加しない                            |
| 工房素材／テンプレート | `src/studio.js`の定義。テンプレート・検証・exportのクレジット表示を一緒に変更                                                                            |
| 保存形式更新           | versionを上げる前に純粋な移行関数と旧版fixtureを用意。先に検証してから置換。未知の版を推測で読み込まない                                                 |
