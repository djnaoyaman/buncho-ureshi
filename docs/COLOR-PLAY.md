# Soft Color Play interface

The selected direction is concept 2's soft, cute shapes with harmonious cream, peach, butter and restrained pale mint. The earlier purpose-based mapping and heavy dark outlines are superseded. Labels, placement, grouping and selected-state underlines explain the actions; color is not a rule assigning a purpose to every feature.

Reading sections use headings, whitespace and occasional dividers rather than a card around every section. Buttons, tappable catalog items and urgent warning states keep visible boundaries. The health heading, caretaker description, rule rows, notebook introduction, memorial reading content and secondary settings sections are deliberately open.

## Preserved scope

No game feature, handler, rule, storage/schema, migration, saved state or living-art file changes. The original game.css baseline remains intact before the UI layer. Birds and the owner retain their art, dimensions, crop and animation. The previous position-only owner adjustment prevents concealment by the home dock. No character redesign is bundled into this change.

The ten menu routes remain, ordered in related pairs: health/profile, relationships/family tree, roster/bird notebook, diary/memorial, settings/help. Relationships and family tree are adjacent on phone and desktop. All bird selection, clean/pause, visitor dismissal, care/conversation, decoration/filter/draw, twelve gardens, warnings, settings, export/import and reset-cancellation controls remain.

The decoration label is consistently お飾りガチャ. Its existing one-draw action says ガチャをまわす and shows 1回 · 20 Gems. Costs, probability, availability, refunds and random-result handling are unchanged. Small phones compact only decorative UI and spacing; no explanatory text or controls are hidden.

Phone notebook cards use two columns, with original artwork proportions and the existing 85px image height. Crow/raptor detail pages group the existing garden, home and enemy-record destinations; emergency escape and global close controls remain.

## Verification and release

Run syntax/content checks, the complete Node suite, dedicated Color Play cross-browser checks, responsive/decoration/lifecycle/notebook/family/scene gates and visual inspection of actual Japanese-font screenshots. Compare broad-suite failures against the existing baseline; a stopped or cancelled run is not a full pass.

The browser suite exercises actual treatment and caretaker actions against the unchanged engine, one gacha draw with exact result/cost, two-column notebook navigation, all menu routes, saved-state/reload, export, invalid import and reset cancellation. It compares living-art source, dimensions, crop, transforms and animations with the theme removed. Short-phone tests require the complete decoration filter to be initially visible, and profile/family shortcut tests guard against legacy CSS overriding their rounded shape.

The user approved the selected direction and subsequently requested deployment after validation. Release only the verified candidate, check main and deployed assets against it, and keep the character work separate and sequential.
