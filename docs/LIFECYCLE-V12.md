# 時計と長く続く家族の記録

現実の1分をゲーム内1時間に統一する。365日換算の10年は現実の約60.83日。成長段階は既存のゲーム上の12・24・48時間を維持し、実際の飼育目安とは扱わない。

旧v1〜v11は厳格に検証してからv12へ移行する。既存の年齢・経過tick・名前・ゲージ・履歴の日付・死亡情報を保持し、新しい時計の起点を移行時刻へ置く。移行直後に以前の短い時計を新時計として再計算しない。移行前の原本は自動保存先に別途保持し、設定から書き出せる。

長い不在では既存の鳥の年齢・成長・寿命と現実のお世話期限を進める。新しい来訪・交際・産卵を大量に再生しない。短い不在では通常処理を続ける。病気・けが・3日間の放置など現実の期限は従来通り。

活動中の128羽枠とは別に、旅立った鳥の記録をarchiveへ保存する。親子・名前・お墓・日記からの参照を保持し、再来訪する友達は同じIDで活動枠へ戻す。日常日記は最新240件、重要な家族の出来事はjournalへ継続保存する。保存形式の物理上限は64MBで、無限保存とはしない。旧形式の表示は旧時計の記録と明記し、新しい記録は現実の日付を使う。

会話と撫でる操作は元気100でも可能。会話の返事と反応を残し、お世話報酬は追加しない。家族の節目は日々の交流予算から独立して一度だけ加点する。入居10・つがい30・産卵25・孵化35・成長20 Gems。

死別時は現在のつがいを解除して過去の家族日記を保持する。新しいつがいは相談して承諾した時に成立する。死別から48ゲーム時間、同じ相談を見送ってから168ゲーム時間の間隔は今回採用したゲーム上の調整値。病気・近親・年齢などの既存条件も適用する。けがの相性閾値を60へ見直し、実際の最小相性51.1で成立しなかった経路を解消する。

天敵の説明は実装の定数を参照し、出現3秒後の25%判定とカラス・猛禽5対5を表示する。

## 長期不在の処理順の修正

2026-11-09の再点検後、利用者が「既存履歴は変更せず、今後の長期不在を発生順に計算する」
範囲を承認。基点は `dcbafcac7a30ae2db318a372148a7a5d9bc4fbe5`。

5ゲーム時間以上の追いつきでは、成長・寿命・既に分かっている治療/給餌期限・飼育員の
契約終了・訪問終了の節目を日時順に処理する。1時間ずつ交流・来訪・産卵を再生しない。
端数の秒は次のゲーム時間へ残す。死亡と成長が同じ瞬間なら既存の死亡判定を先に行い、
同時刻の死亡を全羽について確定してから、家にいる子の代替わりを行う。

新たな病気の判定とゲージのお世話枠は、従来どおり再開時の観測に残す。
見ていなかった間に新しい病気・診断・治療期限切れを作らない。
外にいた後継の帰宅とお世話の開始は再開時とし、治療が必要な子へ従来の通院猶予を残す。
停止中の現実の期限と、短い不在の通常シミュレーションは維持する。

同じ親子を4日後に一度だけ開く場合と、100分後を挟んで開く場合で、孵化tick12・幼鳥36・
成鳥84の日付、放置期限の死亡tick4320、Gems95、乱数列が一致する。
比較対象はこの不在中の既知の出来事。操作・通常交流・お世話枠・新しい病気の観測がある
すべての開き方で、世界全体を同じにする仕様にはしていない。

保存形式はv12のまま。既存の日記・死亡日時・段階・残高を補正、蘇生、補償しない。
修正前の合成v12保存を凍結した `tests/fixtures/absence-v12-before-chronology.json` は、
旧実装 `dcbafca` の不在処理から生成したもので、実利用者の保存ではない。
この保存の卵の墓・tick0の死亡・Gems20を、そのまま保持できることも検査する。

戻す場合は処理順の変更を検査と一緒にrevertする。修正後に正しく生成された新しい日記や
報酬を巻き戻すことはしない。旧保存の原本・リセット用バックアップは引き続き独立して保持する。

最終ローカル検査: 全Node 1,551件（失敗・skipなし）、構文382 JSと37記事・42写真・30問が合格。
Chrome/WebKitの起動・移行・旧保存保持・通院・契約・端末案内/回転の52件も合格。
このうち追加した不在処理の単体検査は18件。複数の区切り方、端数時刻、期限の前後、同時死亡、
家にいる後継と外にいた後継、archiveの成長・寿命、現実の病気の観測、旧履歴保持、
時計の巻戻り、同時に再開した2タブの一度だけの報酬を含む。

## 2026-11-10 短い再開区間の時刻

1〜4ゲーム時間の通常進行も、経過した各1分と既知の健康期限を発生順に処理する。
例えば10→13分で開いた場合、tick12の孵化は13分ではなく12分に記録する。
期限が2分30秒なら、死亡日時は2分30秒、完了済みtickは2として残す。
通常の来客・交流・乱数を省略する長期不在の処理へは置き換えない。
新しい病気の観測と、外にいた後継の帰宅・通院猶予は引き続き再開時に行う。
既存の死亡・記録・年齢・残高は書き換えず、保存版もv12のまま。

このため、成長直前を含む短い区切りでも既知の成長日時と節目報酬が保たれる。
ただし、通常の来客・交流と病気の観測はプレイのしかたに依存する既存仕様で、
あらゆる区切りで世界全体や乱数列が等しくなることは要求しない。
4分の通常進行と1分ずつ4回の進行は、健康・お世話の境界を含まない合成例で
来客、鳥、行動、乱数、日記、通貨が一致することを検査する。
戻す場合はこの短い区間の修正と検査を一緒にrevertし、生成済みの履歴を巻き戻さない。
