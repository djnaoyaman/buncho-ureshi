## 2. スマホ入力の文字サイズ（中・別変更で対応）

事実: Chromiumで320/360/430px縦と667px横の実CSSを計測した。
図鑑検索・観察日付・観察ノートは13.5〜14.4px、縦向きのゲーム会話は15px。
工房のテキスト入力は16px。上記の通常表示では文書の横スクロールはなかった。
iOSの入力時自動拡大を誘発する可能性があるが、本環境で実機キーボードは確認しない。
最小案はスマホ幅とタッチ環境の入力文字を16px以上にし、折返し・内部スクロールを検査する。
色・画像・画面構成・導線を保つ。保存・時刻・成長・来客・通貨処理は変更しない。

対応範囲はゲームと図鑑・観察室・工房を含むサイト。320〜430px縦、568〜932pxの高さ、
667/844px横と短い表示領域、拡大文字を検査する。固定端末幅へ限定しない。
タブレット・PCの既存画面とアクセスは維持する。安全領域とvisualViewportの既存処理を利用し、
音声は既存の利用者操作開始・音OFF設定を保持する。
実機のノッチ、OS文字拡大、キーボード、音声出力はユーザーの手動確認に残す。

## 検査・公開手順

1. 小変更ごとにdiffとmainの更新・既存PRとの重複を確認する。
2. `npm run check`、`npm test`、関連する既存Playwright検査を実行する。
3. ビルド中に画面検査を並行実行しない（distはビルド時に置換される）。
4. 公開は既存の `Verify and publish` の検査を維持して実行し、Actions成功と配信版を確認する。
5. 失敗した検査を削除・skipして公開しない。戻す場合は該当変更のrevertを独立変更として公開する。

既存の未マージPRは10件。特に#103/#47/#45等には現在のUI向け検査更新が含まれる。
それらのPRを勝手にマージ・終了・削除しない。今回の新規検査は別ファイルに置く。
スマホ優先は既存PC画面の削除、ゲームルール変更、schema変更を意味しない。
仕様変更が必要な問題が見つかった場合は、その点だけ確認する。
