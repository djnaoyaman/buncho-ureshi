# お世話ルールの比較試算

作成日 2026年11月12日。再現コマンド `node scripts/compare-care-rules.mjs`。実測や児童による評価ではなく、採用前の経済モデル。ゲーム本体はこのモデルを読み込まない。

## 前提

初期ゲージ100、獲得Gems 0、月曜開始。同じ家族が継続し、1日1回は21時、3回は8・18・21時。各訪問で不足を20ずつ満タンまで回復。初期20 Gems、初心者祝い、成長、贈り物、庭、落とし物は含めず、その他Gemsは0。物語停止を想定するが、現行健康期限は別に進む。落とし物を回収する遊びはこの表の到達時点を早め得る。ガチャの価格だけを20/50/100として、確率・重複返却・所持品は変更しない。

Rは実回復20につき食事6・交流5 Gemsを累積計算。Hは比較用に家庭30 Gems/訪問日と、回復分を家庭10 Gems/日までの追加分として仮置き。持ち越しはしない。Hの基礎受取とGold受取を各1操作と数える。飼育員は最初に全期間分を払える残高を確保して契約。Gold収支は既存30/訪問日から24/契約日を引く。低残高例では無料契約にしない。

到達は開始からの日数。購入間隔は、各価格だけを繰り返し購入したときの獲得累計から算出した平均日数で、同じ訪問内の複数購入も含む。Goldでの飾り購入は混ぜない。最終日の集計は21時まで。

**週末のみ・3日不在は、現行健康ルールのまま実現できる収入予測ではない。** 家族が生存し続けると仮定した経済の潜在値であり、現行72時間期限と衝突する。休暇保護を採用する場合も、既に亡くなった鳥を戻す方式にはしない。

## 判断に使う要点

- Rは同じ総回復量なら端数を持ち越して同じ報酬になる。一方、下限に到達する不在や飼育員による自動回復では、手動回復の量が減り、直接Gemsも減る。
- Hの基礎は訪問日あたり30で、1羽/6羽、1回/3回、契約の有無で変わらない。追加分は最大10までで、契約中は0。この総額差を許すか、追加を0にするかが判断点。
- 通常条件で30/日のRは約16.5 Gems/羽/日。従来の全3枠を埋める66 Gems/羽/日とは大きく違う。既存の30 GoldはGemsとは別通貨なので、補填として合算しない。
- 朝/夜でHの基礎は同じ。回復量の差は開始から最初の訪問までの経過時間による。時間帯の特別報酬はない。
- 満タン維持はこの比較のGold受取条件に残る。生活への誘因を完全に解消したモデルとは言えない。基礎Gemsを受け取るためだけの満タン条件はHにはない。
- 落とし物8 Gemsは現行では給餌後のしぐさと物語時間で発生する。本モデルでは回収0とし、通常操作の満腹再給餌で新たな発生待ちを作らないことを実エンジンのテストで別に確認する。連続減少を採用する前には、微小回復から落とし物を繰り返す経路も、追加上限に含める設計を確定する必要がある。
- これは学校・睡眠への無影響や楽しさを証明しない。家庭での任意の感想、短時間で終えられるかは未計測。
