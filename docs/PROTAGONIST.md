# 主人公の代替わり

## ルール

- 最初の主人公は保存ID `b1` のおもち。名前や選択中の文鳥では判定しません。
- 現在の主人公が旅立つと、その主人公の存命の実子のうち最も先に生まれた子が引き継ぎます。性別で優先順位は変えません。同じゲーム時刻に生まれた場合は、生まれた順のIDで決めます。
- 死亡判定は全員分を済ませてから候補を選びます。同じ更新で亡くなった子に一瞬だけ引き継ぐことはありません。
- 最年長の子が卵の場合は、その子の孵化を待ち、ひなから主人公になれます。お出かけの姿は従来どおり幼鳥・成鳥から表示します。
- 存命の子がいない場合は代替わりを待ちます。知らない鳥への置き換え、初期化、名前の付け直し、鳥の削除はしません。
- 巣立った子が最年長なら、同じIDのまま帰宅して引き継ぎます。家族が6羽の場合は空きを待ち、誰かを追い出しません。帰宅から給餌の期限を数えます。外で保留されていた病気の期限が過ぎている場合も病気は治さず、見える通院時間を1日確保します。
- 次の主人公が亡くなった場合も、その子の最年長の存命の子へ同じ規則で引き継ぎます。先代の別の子に戻すことはありません。
- 現在の主人公とそのつがいは、自動の巣立ちで家を出ません。庭の主役と「自分＝名前」の星印は、どの鳥を選択していても保存された主人公に付きます。

## 残るもの

先代のID、名前、血縁、つがい、思い出、お墓と祈りの回数は残ります。Gold、Gems、持ち物、家具はそのまま。日記に代替わりを一度だけ記録し、歴代主人公のIDを保存します。無料で起こるゲーム内の出来事で、通貨の支払いや報酬はありません。

## 保存形式 v9

新しい `protagonist` は `{version:1,birdId,lineage}`。`lineage` は `b1` から始まる重複しない実子の連なりで、最後のIDが現在の主人公です。先代全員が死亡していること、IDが既存の鳥を参照すること、家族のつながりを厳格に検証します。

v1〜v8は検証後に移行します。v8からは主人公の記録を追加するだけで、健康、実時間の期限、財布、家族、過去の出来事を変更しません。移行自体は時間を進めず、最初の通常更新で全員の死亡判定を終えてから代替わりします。これにより、期限切れの子が誤って継承することを防ぎます。

保存キー、IndexedDBのトランザクション、古い画面のrevision/worldId保護は維持。v8の古いクライアントはv9を上書きできません。明示的な保存全体の復元では、その保存の主人公・歴代・死亡状態を復元し、今の庭と混ぜません。実利用者のデータを検証やリセットに使いません。

## 検査

`tests/protagonist.test.js` は出生順、男女、同時死亡、孫への継承、子なし、孵化、帰宅、定員、旧保存の期限、読み込みの競合、破損保存、復元、9つの庭を検証します。

`playwright.protagonist.config.js` は Chromium touch / WebKit touch / desktop の18ケース。本人印、先代の墓、祈りの保存、操作中の代替わり、3代目、子なし、v8移行、画面の狭幅・広幅と再読込を確認します。既存のhome-visits検査では本人の改名・同名家族・他の鳥の選択も確認します。
