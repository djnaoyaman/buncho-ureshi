## 1. 過去の友達のおうちで描画が停止する（高・修正対象）

事実: `src/friend-cages.js:friendCage` は活動中の `world.birds` だけを検索していた。
`src/engine.js:travelTo` / `fieldBirds` はarchiveの友達も対象とするため、正しい訪問先でも
ケージがnullになる。`src/game.js:garden` の画像生成は `.file` を参照し、例外になる。

再現: 世界を作り、最初のdepartedの友達のケージを記録する。その後150羽を生成し、
最初の友達がarchiveへ入ったことを確認。そのIDで `travelTo(world,'friend',id)` を呼ぶ。
`validateWorld` は成功し、`fieldBirds` に訪問先は存在するが `friendCage` はnullを返す。

最小修正: 既存の `allBirds` を使って活動中・過去の両方を検索する。
割り当て式（epoch・個体ID）、画像、名前、家系、乱数列、Gold/Gems、セーブ形式は変えない。
新しい依存モジュールにもビルドの版番号を付け、キャッシュで旧コードを混ぜない。

回帰検査: archive移動前後・保存読込後のケージ一致と保存全体の不変性。
ブラウザで同じ友達のおうちを開き、画像読込・鳥の操作・再読込・保存全体の一致を確認する。
依存関係: 参照修正とビルドのimport版付けを同じ変更にする。
戻し方: この変更をrevertする。保存の移行・初期化・形式変更は不要。

## 2. 長期不在の成長・死亡・日付が計算順に依存する（高・承認後に今後の計算を修正）

追記: この節は初回点検時の事実。利用者の承認後、今後の計算に限る修正を実施した。
処理順・観測時の保護・旧保存の維持は [LIFECYCLE-V12.md](LIFECYCLE-V12.md) に記録する。
以下の再現結果は修正前のものとして保持する。

事実: `src/engine.js:advanceTo` は成長を追いつかせる前に、再開時刻で
`synchronizeLife` を実行する。`advanceAbsentStory` の各段階の時刻は
`Math.max(lifecycle.seenAt, ...)` なので、すでに再開時刻まで進んだ時計から戻せない。
これにより途中の成長日付がすべて再開時刻になり、現実の期限による死亡が成長より先に確定する。

同じ初期状態（2026-11-09 00:00 UTC、親2羽と卵、停止なし、追加のお世話なし）で再現:

| 再開のしかた | 4日後の世界tick | 子の段階 | 死亡日時 | 死亡tick |
| --- | ---: | --- | --- | ---: |
| 4日後に1回だけ再開 | 5760 | 卵 | 11月12日00:00 UTC | 0 |
| 100分後に一度再開し、その後4日後に再開 | 5760 | 成鳥 | 11月12日00:00 UTC | 100 |

後者の孵化tick12・成長tick36・84の日付も、すべて100分後（01:40 UTC）だった。
どちらも現在の `validateWorld` は通る。実際の保存での発生件数や過去の破損範囲は未確認。

影響: 子の段階、孵化・成長の日記、死亡tick、代替わりや家族の節目報酬、成長時の乱数消費に
影響しうる。表示だけの問題として扱えない。既存の死亡・日記を推測で書き換えない。

初回修正案（承認後に実施）: 停止していない不在区間を、成長・寿命・現実の死亡期限の発生順に処理し、
各イベント時刻へ時計を進める。最後に再開時刻へ到達させる。
停止中の現実のお世話期限、旧v11の日付、既存の移行原本、天敵の可視時計は維持する。
まず同じ不在を1回・複数回に分けた場合の成長・死亡日時と、節目報酬の一度だけの付与を検査する。
この修正は保存に残る段階・日時・報酬へ影響するため、範囲確認後に独立変更として行う。
戻し方はコードのrevertだが、修正後に生成した履歴は単純なrevertでは戻らないため、
既存記録の補正と今後の計算の修正を分ける必要がある。

## 3. 公開後回帰検査の赤表示は未解消（中・切り分け）

公開前CI: run `42601327512` は成功。
公開後の全体回帰: run `42604280377` は242失敗・1,806成功・6skip、約5.4時間。

方針: 失敗一覧を残し、同じcommitのローカルビルドで再現する。UI検査は利用者が実際に使える
操作パネルを開く手順へ合わせる。全体検査はローカル配信で維持し、公開URLへの大量アクセスと
公開後の少数の配信確認を分ける案がある。検査削除、成功扱いへの変更、リトライ増加では解決しない。
