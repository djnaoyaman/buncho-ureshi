# 背景更新で読んでいる位置が戻る不具合

2026-11-11、ユーザーのiPhone画面で「暮らしのメニュー」をスクロールすると上へ戻ると報告。
現行コードは背景更新でgame-mainを置き換え、開閉状態だけを保持していた。
メニュー自体のscrollTopが失われることを、修正前の検査で430→0として再現。
ガチャの確率・Gems説明も、独立したスクロール欄が210→0に戻ることを再現した。

## 修正

- 同じ世界・同じ画面の更新に限り、開いたdata-game-detailsの縦横位置を保持。
  折りたたみを開き直した後、フォーカスの復元も済んでから位置を戻す。
- メニュー内のタブ列、家系図の縦横位置、外側の画面・ケア画面も保持。
- おかえり報告は同じ世界・同じ報告のときだけ保持し、新しい報告には引き継がない。
- ヘルプ・設定・健康・紹介・名簿・日記・関係図・家系図の長い画面を点検。
  既存の画面スクロール保持を維持し、フォーカスの復元後にも再適用する。
- 庭のしおり・友達・同行設定、鳥の記録、図鑑には既存の位置保持がある。
  既存の庭や世界が切り替わったら位置を持ち越さない検査も維持する。

画面の位置は表示中のメモリ内だけで扱い、保存形式・ゲーム進行・乱数・通貨を変えない。
別の画面や別の保存世界に、古いメニューの位置を引き継がない。

## 検証

合成保存で背景更新を発生させ、メニュー・確率説明・各長い画面・ケア・帰宅報告の
位置保持と、世界の切替時にリセットされることを確認する。
Chrome/Safari互換WebKitでは320pxと390pxで実際のホイール操作を行い、複数回の背景更新、
ヘルプ・設定・健康・ガチャ説明・ケア画面の位置、保存全体の一致を確認する。
公開は必須検査とPages成功、配信コードの照合後に完了とする。
